# COMAC-Aero-Agent-DOT

Public-source aircraft power-system simulation and agent engineering demonstrator.

> Personal research and education project. Not an official aircraft design, OEM implementation, certification claim, or operational control system. The repository name does not imply organizational endorsement.

## 目标与范围

展示智能体如何完成一个可追溯的系统级工程任务：理解需求，提出方案，调用仿真，检查约束，比较取舍，生成有计算依据的报告，并迁移到未见过的同类任务。

L3 指智能体应用；L4 指样板泛化共享。这是项目组织方式，不是航空安全或自主运行认证等级。

单路电源失效后的关键负载保障，仅作为起步基线。最终样板需要覆盖多工况、多目标、多约束及陌生任务迁移，让观众看懂复杂设计的取舍。

## 当前状态

仅完成任务说明初始化。尚无已验证模型、可运行仿真、实际评测结果或已连接的本地开发设备。以下为实施与验收目标，不是完成声明。

## 候选系统与旗舰复杂度

候选对象：参考公开航空资料建立的电推进／供电系统研究模型。NASA X-57 的公开资料是待核查来源之一；必须先验证资料、许可与参数适用性，不宣称复现真实 X-57 或其他机型。

系统按需要逐步包含：
- 任务阶段变化引起的推进和辅助负载变化
- 电源容量、配电拓扑、母线连接与冗余方案
- 功率、能量和简化热动态约束
- 单一及组合故障、关键负载优先级与降级策略
- 安全约束检查，以及质量、能量消耗或续航代理指标之间的取舍
- 从需求、假设、方案到仿真和报告结论的证据链

不能仅增加画面上的模块数量。至少一个方案选择必须在多项指标之间形成真实冲突，并由仿真展示其后果。使用质量或续航代理指标时，须披露其简化模型和适用边界。

## 数据与安全边界

- 只使用许可允许使用的公开资料、原创代码和明确标注的合成参数
- 区分来源事实、建模假设、计算结果；记录来源、许可、单位与适用范围
- 不上传内部文件、涉密设计、非公开参数、凭证或个人数据
- 公开可读不等于允许复制分发；未确认许可的资料只保留引用
- 动作只作用于仿真，不连接真实飞机或设备控制系统
- 封存评测任务及答案不进入公开开发仓库，避免测试泄漏
- 模型通过软件测试不代表工程有效性已经得到证明，更不代表适航符合性

## 五个无日期验收关卡

### 1. 场景与证据成立
交付系统边界、需求、公开来源清单、参数假设、动作和约束。
通过条件：关键设定可追溯；简化项明确；受众能说清问题；场景价值获得认可。

### 2. 可复现仿真基线
先实现正常、单故障和负载变化案例及固定规则控制器，再扩展任务阶段、热动态、方案变化和故障组合。
通过条件：相同代码版本与配置在约定容差内复现；供需、容量、单位及边界检查通过；明确模型验证范围和局限。

### 3. L3 工程应用闭环
连接需求、方案参数、受约束动作、仿真调用、指标比较、检查与报告。
通过条件：智能体动作实际改变输入或状态；越界动作被拦截；结果可回放；与固定规则或其他简单基线公平比较；失败和不确定性如实呈现。

### 4. 综合能力的直观演示
提供系统图、任务与故障输入、方案对比、动作时间线，以及可展开的证据层。
通过条件：不读代码也能理解哪里出问题、改了什么、保住什么、代价是什么；至少展示一个多约束冲突及取舍；画面与实际计算一致；区分实时计算与回放。

### 5. L4 泛化与共享
冻结版本，交由未参与开发者按说明复现，再测试封存的同类新任务与场景变体。
通过条件：新环境可复现；任务变化主要通过配置或明确适配层处理；未见任务无提前泄漏；完整报告成功、失败、约束违反、耗时与调用成本。

跨设备可运行与跨任务有效分别验收。按关卡结果推进，不以预设周数代替完成证据。

## 三环境协作

- 本仓库是代码和文档的正式版本来源，云端、Mac、Windows 按需使用工作副本
- 云端承担资料研究及适合其条件的开发测试；Mac 优先本地运行与演示；Windows 可用于独立复核，具体兼容性待验证
- 一项任务一个主写环境、一个独立分支；后续改动通过草稿 PR 附带测试证据与摘要
- 交接保存的版本、依赖、输入和运行说明，不依赖永不中断的进程
- 大型轨迹和视频另行安排存储，仓库保存索引、版本及校验信息
- 临时云端目录不是无限或永久存储；费用、设备接入、合并和部署依实际授权处理

## 紧接着做什么

1. 核查候选公开资料，确定可用范围、许可和参考价值
2. 固定需求、系统边界、单位、假设及基线验收测试
3. 在可用执行环境中实现不依赖大模型的确定性仿真
4. 基线通过后接入智能体，再扩展综合约束与演示

优先复用成熟 Harness。自定义开发聚焦状态、合法动作、仿真、记录回放和评测接口，不先建设通用代理平台。
