# 公开来源、热约束与建模边界

核查日期：2026-09-30。本文只记录公开资料与本项目的建模边界，不构成真实飞机设计、运行指令或适航符合性证据。

## 先读结论

NASA X-57 可作为系统架构和工程问题的公开参考，但本项目是 **X-57 启发的合成系统演示**，不是 X-57 数字孪生。没有核实到可直接复现完整 X-57 电气、热、任务和控制系统的开源可执行模型。X-57 项目在飞机飞行试验前结束；不要把地面试验、分析预测或目标性能写成已验证的飞行性能。

首要问题是热约束，其次是组合故障，再比较质量代价。正常、单故障与固定规则控制器都是必要基线，不是最终复杂度。

## 六组高价值来源

### S1 — 最终供电与指令架构

- 名称：X-57 Traction Power and Command Systems Development
- 发布：2024-09-09；NTRS 收录：2024-07-25
- 记录：https://ntrs.nasa.gov/citations/20240009560
- 日期交叉核查：https://www.nasa.gov/directorates/armd/x-57-technical-papers/
- 定位：PDF 第 3 页 Figure 1/2、第 4 页指令与航电变更说明；正文电池和保护设计章节
- 用途：最终架构、冗余依赖、集成修改、试验与保护经验
- 关键事实：A/B 两组牵引电池分别通过控制器通道服务左右两个巡航电机，不能简化成左电池仅供左电机。翼上控制供电依赖必要母线，低压供电故障可以影响仍有高压能量的推进系统。
- 缺口：未核实完整可执行模型、机器可读接线网表及全部保护逻辑。不能从图中自行推断任意高压母线互联能力。
- 权利：NTRS 标注 Public、Work of the US Gov. Public Use Permitted。

- 缺口：文中提到的 GRC 电池模型未核实可下载；图表数字转录后仍需单位、总量和配置复核。

### S4 — 热约束主证据

- 名称：Cruise Propulsion System Thermal Analysis for NASA’s X-57 “Maxwell” Mod II Configuration
- 时间：2023 年 AIAA Aviation（2023-06-12 至 06-16）；NTRS 收录 2023-05-04，记录未单列精确出版日
- 记录：https://ntrs.nasa.gov/citations/20230006888
- 定位：Table 1 温度限制；Table 3 三个工况；Table 4 损耗；Table 6 预测温度和裕度；附录流动边界
- 用途：证明任务阶段、损耗、空气流动和部件温度之间需要联合分析，不能仅检查瞬时电功率。
- 关键事实：研究对象是 Mod II 的被动空气冷却机舱；低速热天初始爬升是关键散热工况。论文计算中两个控制板超过项目留裕度温度不足 2°C；这不等于实测超温事故，也不等于超过硬件极限。
- 缺口：这里的公开结果主要是稳态工况；未核实完整 CFD/热求解器或瞬态热容。用稳态点拟合模型不能证明延迟升温曲线正确。
- 适用边界：Mod II 冷却结果不能不加说明地用于 Mod IV 翼尖机舱。
- 权利：NTRS 标注 Public、Work of the US Gov. Public Use Permitted。

## 从证据到合成模型

以下是本项目允许采用的低阶研究假设，不是 NASA 发布的完整仿真模型：

1. 电气层：使用显式的 A/B 支路、负载接入和低压使能状态。若为简化采用聚合母线，只能声称聚合能量/功率分析；不能声称已验证独立支路冗余。
2. 电池层：SOC 积分与简化开路电压/内阻。合成容量、内阻、效率和电压映射必须单独标记。
3. 热层：使用 `C * dT/dt = P_loss - UA * (T - T_ambient)` 或等价低阶网络。C 的单位为 J/K，UA 为 W/K，损耗为 W；代码若用 kW，必须显式换算。每个热节点对应的实际部件范围应说明。
4. 功率恢复不代表温度立即恢复：损耗、热容量和散热共同决定温度变化，热峰可能滞后。是否出现、何时出现，只能由本次模型和输入计算；不能预设一条必然的“恢复后超温”剧情。
5. 温度阈值分层：设计裕度线、降额/保护线、模型硬约束不能混成一条。未校准时它们均为合成测试阈值，不能借用 NASA 数值使其显得已验证。
6. 组合故障：故障时刻、严重度和冷却能力折减是测试设定，不是 NASA 已验证的故障序列。即使每个单故障可行，组合后仍可能无可行解；报告须允许所有策略失败。

## 离线设计与在线动作必须分开

- 离线方案参数：散热面积/通道、热容、散热能力、冗余结构、电池容量、安装质量。它们在一次任务运行中保持固定。
- 在线控制动作：在已存在的支路和额定值范围内调整功率分配、卸载明确可卸载的负载、降额或改变合成任务需求。
- X-57 参考机舱采用被动空气冷却，不应凭空提供“调大冷却泵”按钮。若另设主动冷却合成架构，须说明新增泵、功耗、限值、故障和质量模型。
- 更大散热能力的质量增量不是任意免费收益。若缺乏可信几何/材料模型，只能作为明确的质量代理指标；不能直接称为真实飞机重量或航程变化。

## 公平比较与审计要求

- 固定规则基线也必须保留合理保护/降额功能。晚些时候可能表现为保护动作导致供电不足，而非硬件温度越限。
- 所有策略使用相同任务、故障、初始状态、物理约束和预先声明的信息权限。预测控制器是否提前知道故障，必须说明。
- 不预设智能体获胜；展示任务满足、保护动作、未满足能量、温度裕度和质量代价。改善一项指标可能损害另一项。
- 数值稳定、守恒与软件测试通过，只验证对应软件性质；不证明模型与真实飞机一致。
- 每个参数记录：值、单位、适用配置、来源 ID/页码、测量/估算/合成类别、版本及不确定性。每次运行记录代码版本、配置、动作、约束结果和失败原因。
- 当前公开示例属于开发案例。真正未见任务应在模型和策略冻结后由独立方封存提供，不能把已调参示例称作盲测泛化成功。
